営業・集客部門向け 商談生成AIエージェント

見込み客を集め、育て、
「商談生成」をAI社員に任せる。

Facebook、LinkedIn、Xなどの接点から見込み客候補を見つけ、反応を整理し、アプローチ候補を出し、DMやフォローを準備する。営業担当が毎回ゼロから商談をつくるのではなく、「商談が生まれるまでの流れ」をAI社員と仕組みで回していきます。

01 接点をつくる市場・競合・ニュースを調べ、投稿を継続生成し、反応を集める
02 商談候補を見つけるCRM照合・条件判定・優先順位づけを行う
03 アプローチを準備するDM・フォロー・再接触文面を下書きする
04 商談につなぐ返信・日程調整・商談化を記録し、人が会話を引き継ぐ
目指すのは完全自動営業ではなく、「商談候補が継続的に生まれる仕組み」です。送信・公開・重要判断は人が担います。
01 CURRENT STATE

商談は、「営業担当が頑張った時だけ」生まれやすい。

新規商談を増やすには、発信、反応者確認、候補抽出、DM、返信、フォロー、掘り起こしを継続する必要があります。ところが、この一連の活動が人の手作業に依存すると、忙しいほど商談生成が止まりやすくなります。

01

見込み客情報が分散

SNS、チャット、管理表、CRMなど複数の場所に接点情報が残り、全体像をつかみにくい。

02

候補抽出が手作業

誰に声をかけるかを毎回人が探し、優先順位づけまで担当者の経験に依存する。

03

入力と転記が多い

送信結果、返信、商談化、次回アクションなどを複数の場所へ入力し直す作業が発生する。

04

追客が記憶頼み

「いつ、誰に、何を送るか」が個人の記憶やカレンダーに依存し、フォロー漏れが起きやすい。

05

文章作成が毎回ゼロから

DM、お礼、リマインド、追客など、似た文章を毎回考えるため時間がかかる。

06

商談前の調査がばらつく

会社情報や過去接点の確認品質が担当者ごとに異なり、準備の抜け漏れが生まれる。

07

商談後の更新が後回し

議事録、CRM更新、次回アクション、お礼作成が商談後にまとめて発生し、入力が遅れる。

08

判断と作業が混在

本来は人が担うべき営業判断と、機械でよい定型作業が混ざり、担当者の負荷が高くなる。

02 WHY AI AGENT

「聞いたら答えるAI」から、「決めた条件で動くAI」へ。

通常の生成AI

毎回、人が仕事を頼む

  • 人がプロンプトを入力する
  • その場の回答を受け取る
  • 次の作業はまた人が指示する
  • 記録や通知は別作業になりやすい
AIエージェント

条件に沿って、確認・整理・準備する

  • 決めた時間や条件で対象を確認する
  • 必要な情報を集めて整理する
  • 文面や次回アクションを下書きする
  • 人に「判断すべき状態」で渡す
重要なのは「AIが営業担当の代わりにクロージングすること」ではありません。見込み客の発見・整理・アプローチ準備・フォローを継続し、商談候補を営業へ渡す仕組みにすることです。
03 ROLE DESIGN

商談生成を仕組みにしながら、人の役割は残す。

AI社員が見込み客候補の整理や文面準備を担い、システムが定刻実行・記録を担う。営業担当は、返信後の会話・商談・重要判断に集中します。

人が担う

  • 重要顧客への対応
  • 承認・最終送信
  • 価格や条件の判断
  • 例外対応
  • 関係性をつくる会話

システムが担う

  • 定刻実行
  • 条件判定
  • データ取得
  • 転記・同期
  • 通知・ログ記録

AIが担う

  • 要約・分類
  • 文章の下書き
  • 優先順位づけ
  • 事前情報の整理
  • 次回アクション案
04 CHANNEL EXAMPLES

Facebook・LinkedIn・Xを、「発信」で終わらせず商談につなげる。

SNSごとに役割は異なります。大切なのは、投稿や接続申請そのものではなく、その後の「反応者の把握 → 候補化 → アプローチ → フォロー → 商談化」までを一つの流れとして設計することです。

FACEBOOK

投稿反応を、DM候補へ変える

投稿へのいいね・コメントなどの反応者を取得し、CRMの人物情報と照合。役職や過去接点などをもとに優先度を付け、DM候補として営業へ渡します。

例：投稿 → 反応者取得 → CRM照合 → 優先順位 → DM下書き → 人が確認・送信 → 返信を商談候補化
LINKEDIN

接続後のフォローを止めない

条件に合う見込み客候補を整理し、接続状況を管理。つながった相手にはお礼DM、その後のフォロー候補や日程調整への導線を準備します。

例：候補抽出 → 接続申請 → 承認確認 → お礼DM → 数日後フォロー → 日程調整 → 商談化
X

発信を、接点形成の入口にする

他チャネルで作った発信内容をX向けに展開し、投稿実績や反応を記録。直接の自動営業ではなく、認知・接点づくりの入口として活用します。

例：発信テーマ整理 → 投稿案作成 → 人が承認 → 投稿 → 指標・返信を記録 → 有望な反応は人が確認

SNS運用の目的を「投稿数」から「商談生成」へ。

発信、DM、フォロー、掘り起こしを別々の作業にせず、CRMとつないで「誰に、いつ、次に何をするか」が出てくる状態を目指します。

05 CONTENT PDCA

投稿を「作って終わり」にせず、商談につながる発信へ改善し続ける。

AI社員は、投稿文を自動生成するだけではありません。事前リサーチ、ベンチマーク分析、テーマ選定、投稿案生成、結果集計、振り返りまでをつなぎ、次回の発信に学習結果を反映します。

市場・ニュースを調査
競合・参考投稿を分析
投稿テーマを提案
投稿文を自動生成
反応・結果を集計
仮説を更新
リサーチ → 生成 → 公開 → 計測 → 振り返り → 次回生成、までを1つの運用として回す。
RESEARCH

投稿前の事前リサーチ

業界ニュース、顧客との会話、動画・記事などから、今発信する価値があるテーマ候補を収集。AIが要点を整理し、投稿ネタとして使える状態にします。

BENCHMARK

ベンチマーク投稿を分析

参考アカウントの公開投稿から、冒頭の入り方、文章構造、テーマ、反応傾向などを分析。文章をコピーするのではなく、反応されやすい「型」を学びます。

GENERATION

翌週分の投稿案をまとめて生成

ネタ在庫、過去の投稿実績、テーマの偏り、直近の仮説をもとに複数本を自動生成。人は内容を確認・修正し、公開可否を判断します。

MEASUREMENT

投稿結果を自動で蓄積

投稿後の反応や問い合わせなどを記録し、「どのテーマ・切り口・導線が反応につながったか」を比較できる状態にします。

LEARNING

AIが振り返りと仮説を出す

一定期間ごとに投稿成績を比較し、伸びた要因・弱かった要因を整理。次回試すテーマや構成を「仮説」として提案します。

LEAD GEN

反応者を商談生成につなげる

投稿への反応を単なるエンゲージメントで終わらせず、CRMと照合し、見込み客候補として整理。発信PDCAを商談生成PDCAへつなぎます。

AIが回すのは「投稿作成」ではなく、「発信から商談までの学習サイクル」。

人が毎回ネタを探し、文章を書き、結果をExcelで振り返るのではなく、AIとシステムが情報収集・生成・集計・分析を継続。人はブランド判断、最終承認、顧客との会話に集中します。

08 BEFORE / AFTER

「営業が自分で商談を探す」から、「商談候補が毎日届く」へ。

Before

  • 毎回ネタを探して投稿を書く
  • SNSを見て候補を探す
  • 誰にDMしたか思い出す
  • 返信・未返信を手作業で確認する
  • 毎回DMを書く
  • 追客日を自分で管理する
  • 忙しいと新規開拓が止まる
→

After

  • リサーチ済みの投稿案が継続的に届く
  • 投稿結果から次の仮説が更新される
  • 商談候補が一覧で届く
  • 過去接点が整理されている
  • DM・フォロー案が用意される
  • 返信・未返信が整理される
  • 再接触すべき相手が通知される
  • 人は返信・商談・クロージングに集中する

10 ROADMAP

小さく作り、実際に使い、広げる。

PHASE 1

1つの集客・商談生成レーン

まずは「Facebook投稿PDCA→反応者DM」や「LinkedIn接続後フォロー」など、1つの入口に絞って仕組み化する。

PHASE 2

複数チャネルへ展開

Facebook、LinkedIn、既存顧客、交流会など、複数の入口から商談候補が集まる状態へ広げる。

PHASE 3

商談生成エンジン化

CRMを中心に、発信・反応・DM・フォロー・掘り起こし・商談化までを継続運用できる状態にする。

小さく作る → 使う → 改善する → 広げる

最初から全営業プロセスを変えず、効果を測りやすい1業務から運用を固めます。

11 BOUNDARY

できることと、最初から約束しないことを分ける。

現実的に狙えること

  • 入力・転記負荷の削減
  • 情報の整理と要約
  • Facebook・LinkedIn等の商談候補整理
  • DM・お礼・追客文の下書き
  • 期限リマインド
  • 追客候補・休眠顧客の抽出
  • 商談前準備の標準化
  • 活動ログの蓄積

最初から約束しないこと

  • 完全無人化
  • 完全自動営業
  • すべてのツールとの自動連携
  • 重要顧客への無承認送信
  • 価格・契約条件の完全自動判断
  • 人間の確認ゼロ
  • 100%の正確性
